# ACCEPTANCE —— K2 首轮真实笔记校准（2026-10-24）

> 触发：用户真实试用（20 篇线性代数笔记，NotebookLM 风格）反馈「很多地方显示
> 『原文无可识别核心知识块』，但其实有挺多知识点」。本文件如实记录根因、修复与验证。

## 根因（代码级）

1. **列表项永远进不了核心层**：`segmentMkus` 对 listItem 只有两条路——
   `由/因为/所以…` 开头 → derivationStep，否则一律 background。而真实笔记的
   主要知识载体是 `**加粗术语**：解释` 列表，全部被判为背景层 → generic 课时
   core=0 → 进入「原文转写模式」。
2. **分类器信号正则被 Markdown 标记遮挡**：`定义[::：]` 匹配不了 `**定义**：`
   （中间隔着 `**`）→ 定义信号计 0 → 误判 generic。
3. **有序列表项全部计为推导信号**：性质/运算律的编号枚举也推高 derivation 分。
4. **公式块无条件给推导课加分**：性质课满是公式 → 误判推导课（1-3、索引页受害）。
5. **行内公式内容污染信号统计**：公式里的 `→/⇒` 计入推导信号。
6. **`**第一步：**`（冒号在加粗内部）不识别**；例题区有序列表步骤不识别。
7. **索引/总览/章末总结页被当知识课编译**。

## 修复（全部确定性规则，COMPILER_VERSION 1→2）

- 新增 `src/core/model/cues.ts`：净化文本（去列表前缀/强调标记/行内公式）+ 加粗
  引导语提取 + 全部线索正则集中管理。
- `mku.ts`：段落与列表项共用线索解析器（定义/性质/易错/例题/解答/推导/练习）；
  标题建立章节上下文（定义/性质/推导/例题）；例题区有序列表 = 解答步骤链；
  性质/考点区表格与 ⚠️ 提醒引用块归相关知识层。
- `type.ts`：信号统计在净化文本上进行；例题信号扩展到标题与加粗步骤引导；
  公式块加分须伴随推导信号；有序步骤须在推导小节内；目录/导学/「本章」总结页
  → generic 通用讲解。
- `compile.ts`：generic 兜底纳入 related 层知识块（基线 §8「讲解→小结」）；转写
  模式仅用于连相关知识都识别不出的结构异常场景。

## 验证

- 单测：199/199 全绿（188 既有零回归 + 11 项新增校准用例
  `tests/k2-mku-calibration.test.ts`，覆盖真实笔记样式 A–E 的等价改写）；
  `npm run check` 退出码 0。
- 真实数据（用户浏览器实测，19 课时批量重编译）：**「原文无可识别」0 处**
  （修复前大量课时处于转写模式）。结果分布：8 concept / 3 example / 3 derivation /
  5 generic（索引×3、1-3 性质表、3-4 考点表、3-3）。
  - 3-1：6 核心定义 + 9 属性辨析，核心覆盖 6/6。
  - 3-2：4 核心定义 + 10 属性辨析，覆盖 4/4。
  - 2-6：例题呈现×16 + 分步解答×12（修复前解答步骤 0）。
  - 1-5：分步解答×9；1-1：分步解答×4。
  - 索引/总览页：通用讲解（口诀、目录内容入讲解，不再伪造推导结构）。

## 已知遗留（如实，K2 下一轮）

1. 混合课型（如 2-2 基本运算、1-1）只按获胜课型取材，其余核心 MKU 进
   「未纳入」清单（如 2-2 为 7/34）——报告诚实、可手动补入，但编译侧
   混合取材策略待设计。
2. A 段内容保留原文 Markdown 标记（`* **术语**：…`），保真优先，观感待优化。
3. 概念课的公式 MKU 不参与任何环节 → 计入未纳入（如 1-2 为 19/21）。
4. K2 转正门禁的三前置（单元边界一致率/tier 一致率/无误报）需按本文件
   样式建立人工核对流程后再评估。
